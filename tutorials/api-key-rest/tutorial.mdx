## What you will build

Two scripts, in cURL or Python (pick one in the code header):

* `create-api-key.sh` / `create_api_key.py` creates the API key credentials and generates the first key, in slot 1.
* `rotate-api-key.sh` / `rotate_api_key.py` rotates that key without downtime, using the second slot.

They send the same requests as the portal's [**New item › Developer credentials** wizard](../api-key-portal/#add-item), so every parameter matches a field in the wizard.

<details>
<summary>Check prerequisites</summary>
<p>An ArcGIS Location Platform, ArcGIS Online, or ArcGIS Enterprise account with a Creator user type or higher and the <strong>Generate API keys</strong> and <strong>Assign privileges to OAuth 2.0 applications</strong> privileges. Ideally a service user with only those.</p>
<p>cURL version: <code>bash</code>, <code>curl</code> and <code>jq</code>. Python version: Python 3 with <code>requests</code> and <code>python-dotenv</code>.</p>
</details>

> Each Result pane shows what that step prints with `VERBOSE=1`, captured earlier with made-up ids, secrets and keys. Nothing on this page sends a request.

</Intro>

## Configure the scripts

Copy `.env.example` to `.env` and fill it in. `.gitignore` keeps it out of your repository.

Every request goes to the portal's <Hint id="sharing-api" label="sharing API">`https://www.arcgis.com/sharing/rest` for ArcGIS Online and ArcGIS Location Platform (your org URL works too), `https://<host>/<web-adaptor>/sharing/rest` for ArcGIS Enterprise.</Hint>:

<VarField name="portalUrl" label="Portal URL" placeholder="https://www.arcgis.com/sharing/rest" persist />

`ITEM_OWNER` is the username in the item URLs:

<VarField name="username" label="Username (owner of the item)" persist />

The scripts sign in with <Hint id="app-credentials" label="app credentials">Backend jobs can't sign in as you: a username and password don't work with SAML/SSO or MFA. Create the app credentials in the portal as a service user and assign them that user's privileges. They are not the client ID and secret of the API key item the script creates.</Hint>, not as you:

<VarField name="appClientId" label="App credentials client ID" persist />
<VarField name="appClientSecret" label="App credentials client secret" secret />

> **Keep the `client_secret` in a secret manager**, and create the app credentials as a service user with only the privileges these scripts need. With admin privileges, the secret can do almost as much damage as your password.

Run with `VERBOSE=1` (`VERBOSE=1 bash create-api-key.sh` or `VERBOSE=1 python create_api_key.py`) to print each response, as in the Result panes. **It prints secrets**: don't use it in scheduled jobs whose output ends up in logs.

<details>
<summary>More details</summary>
<ul>
<li>The variable is <code>ITEM_OWNER</code>, not <code>USERNAME</code>, because Windows already sets <code>USERNAME</code>.</li>
<li>Creating and rotating keys with app credentials needs their owner's user privileges: on ArcGIS Location Platform, <code>createItem</code>, <code>generateApiTokens</code> and <code>assignPrivilegesToApps</code> alone were not enough. The secret can't sign in or change your password, but it can do whatever those privileges allow.</li>
<li>In production, the same variables can come from the environment or a secret manager instead of <code>.env</code>.</li>
<li>Without <code>VERBOSE=1</code>, the scripts print only the item ID and the key.</li>
</ul>
</details>

</Step>

## Sign in

`oauth2/token` with `grant_type=client_credentials`, the client ID and the secret returns an app token. Every request that follows sends it as `token`.

<details>
<summary>Other ways to sign in</summary>
<p>Get the token from <code>generateToken</code> (username and password) or from the OAuth 2.0 authorization code flow; everything after this step stays the same.</p>
<table>
<tr><th>Method</th><th>Use it for</th><th>Limits</th></tr>
<tr><td>Username and password</td><td>Trying things on your machine</td><td>Doesn't work with SAML/SSO or MFA accounts; the password ends up in code or the environment.</td></tr>
<tr><td><a href="https://developers.arcgis.com/documentation/security-and-authentication/user-authentication/">User authentication</a> (OAuth 2.0)</td><td>Interactive scripts and apps</td><td>The refresh token expires, and changing the password invalidates it.</td></tr>
<tr><td><a href="https://developers.arcgis.com/documentation/security-and-authentication/app-authentication/">App credentials</a></td><td>Backend jobs, such as scheduled rotation</td><td>They need their owner's user privileges, and the <code>client_secret</code> can do whatever those privileges allow. Both scripts use them.</td></tr>
</table>
</details>

</Step>

<Step id="add-item" region="add-item" output="add-item.json" view="result">

## Create the credential item

`addItem` creates an empty item of type `Application`. `title`, `tags` and `snippet` match the wizard's [**Item details**](../api-key-portal/#details) screen. Its `id` goes into the next two requests.

</Step>

<Step id="register" region="register" output="register.json" view="result">

## Register the item as an app

`registerApp` turns the item into a credential and returns its `client_id` and `client_secret`. Two parameters set what every key of this item can do:

- `privileges`: the services the key can call, one per toggle on the wizard's [**Privileges**](../api-key-portal/#register) screen. See the [privileges reference](https://developers.arcgis.com/documentation/security-and-authentication/reference/privileges/).
- `httpReferrers`: the domains allowed to use the key. Empty here so you can test from scripts or Postman.

<VarField name="privileges" label="Privileges (comma-separated)" placeholder="premium:user:basemaps,premium:user:geocode" persist />

> **Set your app's URL as a referrer before you ship a public app.** Without one, anyone who copies the key can use it from any site, billed to you. You can't change referrers later without invalidating the key.

> **The `client_secret` is the master credential.** Anyone with it can generate new keys for this item: keep it out of apps and repositories.

<details>
<summary>More details</summary>
<ul>
<li><a href="../api-key-portal/#item-access">Access to an item</a> is the privilege <code>portal:app:access:item:&lt;itemId&gt;</code>.</li>
<li><code>appType</code> and <code>redirect_uris</code> come from OAuth 2.0 credentials: <code>redirect_uris</code> is where <a href="https://developers.arcgis.com/documentation/security-and-authentication/user-authentication/">user authentication</a> sends users back after they sign in. <code>registerApp</code> fails without them, but their values don't affect the key (even <code>redirect_uris=[]</code> works).</li>
</ul>
</details>

</Step>

<Step id="expiration" region="expiration" output="update.json" view="result">

## Set the expiration of slot 1

Each item has two key slots, each with its own expiration date. The dates are item properties, so this is an item `update`, in epoch milliseconds, at most one year ahead.

Set it **before** generating the key: changing it later invalidates the key.

</Step>

<Step id="generate" region="generate" output="create.txt" view="result">

## Generate the API key

`oauth2/token` with the item's client credentials and `apiToken=1` returns the key for slot 1 as `access_token`. The portal shows it only once: deploy it to your app. `state.json` keeps the item ID and slot for the rotation script, but not the key.

<details>
<summary>More details</summary>
<ul>
<li>The <code>client_secret</code> authenticates this call; no user token is sent. Without <code>apiToken</code>, the same request returns a two-hour app token instead.</li>
<li><code>regenerateApiToken</code> is a safety switch. On an empty slot it can be <code>false</code>, <code>true</code> or left out. On a slot that already holds a key, <code>false</code> fails with <code>400 Unauthorized</code>, and <code>true</code> replaces the key.</li>
</ul>
</details>

</Step>

<Step id="rotate-config" region="rotate-config" collapsed>

## Rotate: start from the key in production

Rotation keeps a valid key at all times: generate a key in the free slot, deploy it, then invalidate the old one.

The script loads the same `.env` and reads the item and current slot from `state.json`.

</Step>

<Step id="app-info" region="app-info" output="app-info.txt" view="result">

## Get the item's client credentials

`registeredAppInfo` returns the item's `client_id` and `client_secret`, so the script doesn't need to keep them. `apiToken1Active` and `apiToken2Active` show which slots hold a key.

</Step>

<Step id="find-slot" region="find-slot">

## Find the free slot

The new key goes into the slot that isn't in production. Without `state.json`, <Hint id="key-slot" label="the key tells you its slot">A key ends in `AT1_` or `AT2_` plus eight characters, so the tenth character from the end is `1` or `2`. ArcGIS REST JS reads it that way in `slotForKey`.</Hint>.

</Step>

<Step id="rotate-expiration" region="rotate-expiration" output="update.json" view="result">

## Set the expiration of the new slot

The same item `update`, now for `apiToken2ExpirationDate` (or `apiToken1ExpirationDate` when slot 2 is in use). Staggered dates let one key cover the other while it is replaced.

</Step>

<Step id="rotate-generate" region="rotate-generate" output="rotate-generate.txt" view="result">

## Generate the key in the new slot

The same `oauth2/token` request, with `apiToken` set to the new slot and `regenerateApiToken=true` in case it held an old key. Both keys are valid now.

Never regenerate the slot in production: its key dies the moment the new one is issued, and the app is down until you deploy.

</Step>

<Step id="deploy" region="deploy" output="rotate-deploy.txt" view="result">

## Deploy the new key

Put the new key in production. The old key stays valid until you continue.

</Step>

<Step id="invalidate" region="invalidate" output="rotate.txt" view="result">

## Invalidate the old key

`revokeToken` with the item's client credentials and `apiToken` set to the old slot invalidates that key immediately. The script then saves the new slot to `state.json`.

<details>
<summary>Parameters ArcGIS REST JS adds</summary>
<p>ArcGIS REST JS also sends <code>grant_type</code> and <code>regenerateApiToken</code>, but <code>client_id</code>, <code>client_secret</code> and <code>apiToken</code> are all it needs.</p>
</details>

</Step>
